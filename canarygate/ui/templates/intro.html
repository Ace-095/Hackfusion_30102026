the argument

Anyone can show you a red badge.
This shows you the proof behind it.

CanaryGate tests API authorisation, and it refuses to guess. Every conclusion is attached to the exact requests that produced it — the ownership baseline, the cross-user read, and the disclosure that followed.

01

Evidence before verdict

A finding exists only when two independently captured requests agree: the owner reading their own resource, and a different account reading it afterwards.

02

Nothing is inferred

Status codes, assertions, hashes and counters are rendered from the backend's own records. If the backend could not establish something, the page says “not recorded”.

03

Every claim is replayable

The flight recorder steps through the captured requests in order and reveals the verdict last — so the conclusion can be checked against the record, not taken on trust.

one investigation, seven steps

Follow a Read-BOLA finding from request to verdict.

  1. 1Posturewhat the backend reports about itself
  2. 2Inventoryeach endpoint and the access it expects
  3. 3Scan resultsstored runs, newest first
  4. 4Findingwhy this verdict, in the backend's words
  5. 5Ownership proofthe resource belongs to the other account
  6. 6Disclosure proofprivate data crossed the boundary
  7. 7Matrix & reportcoverage, gaps, and a printable record

the vocabulary

Five conclusions. Each one has a rule.

  • CONFIRMED Ownership and disclosure are both proven. One without the other is not a finding.
  • SUSPECTED Something crossed a boundary, but the evidence is incomplete.
  • SAFE The oracle ran and matched the expected denial — including the denial body.
  • INCONCLUSIVE The backend could not decide from what it captured. Not a pass.
  • SKIPPED The check never ran. Missing coverage, never a green tick.

what this build refuses to do

The limits are on the page, not in the fine print.

  • No live scanning. The API reports mode="fixture" and live_scanning=false. Nothing here touches a network or a real target.
  • Synthetic results. Fixture and transcript runs are recordings. They are not evidence about any real or organiser-supplied API.
  • No severity, no score. Severity is not in the contract, so the interface never invents one.
  • No authentication. This server is local and unauthenticated. Do not expose it.
