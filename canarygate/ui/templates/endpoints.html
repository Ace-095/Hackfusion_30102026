{{ icon("info") }} How to read this table

  • Expected access is the backend's classification: public, authenticated, role:<name>, owner-only or unknown. unknown is a valid answer and can never become a CONFIRMED verdict.
  • Provenance is the source of that expectation. OpenAPI security expresses authentication requirements, not authorization policy, so it is labelled as such. The fixture's owner-only rule comes from the synthetic fixture policy.
  • Recorded verdicts only appear when a stored run targeted that exact endpoint. Empty cells are missing coverage, not safety.

{{ icon("lock") }} Uploaded specifications stay separate

A specification you inspect on the spec page is parsed in memory and discarded. It never changes this inventory, never selects a target and is never scanned.

Connecting an uploaded specification to a scan requires the guarded runner, a written scope and organizer authorization — not implemented.
