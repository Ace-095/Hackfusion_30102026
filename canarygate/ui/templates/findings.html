Findings

Every conclusion the backend has recorded, grouped by verdict. A conclusion only exists because a stored run produced it — this page groups and explains, it never adds a finding of its own.

Severity is not part of the backend contract. The backend returns a verdict (CONFIRMED, SUSPECTED, SAFE, INCONCLUSIVE, SKIPPED), a reason, a decision checklist and a remediation key — no CVSS, no severity label. This page therefore ranks by verdict and never invents a score. See docs/UI.md (gap G6/R6) for the proposed contract addition.

How a finding is allowed to exist

  • CONFIRMED requires proof that the resource belongs to the other account and proof that the acting account received that account's private data. A 200 response alone is never enough.
  • SAFE is only recorded when the oracle ran and matched the expectation, including a verified denial.
  • INCONCLUSIVE / SKIPPED stay visible here so coverage gaps cannot be mistaken for security.
  • Every finding carries a redacted request/response summary with its own SHA-256; the evidence explorer shows them side by side.
