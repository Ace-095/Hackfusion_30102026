An account is marked verified only when a stored owner-baseline check returned that account's own record with a recorded status. The run that proved it is linked, and the check id resolves to that row on the run page.

The SHA-256 above is the digest of the check's content — its id, verdict, flags and bounded evidence — within the run named beside it. It is not a digest of the response body: bodies, tokens and private markers are never stored. A row is identified by the run id and the check id together, which is why both are printed.

{{ icon("shield") }} What this does and does not prove

It does prove

  • two distinct identities authenticated over real HTTPS and each held its own token;
  • each account's own record was returned to that account, and the record's private marker matched the owner baseline the oracle verified;
  • the cross-account list did not contain the other account's private record, so the proof does not rest on a shared listing.

It does not prove

  • anything about a live or organizer-supplied API — the lab is loopback-only and written by the same team;
  • that an account owns more than the one asset the catalog declares;
  • that a record body is safe to disclose: bodies, tokens and markers are never stored, only booleans and digests.
