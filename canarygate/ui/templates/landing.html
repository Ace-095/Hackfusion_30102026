What the platform actually does

Three capabilities, all of them backed by stored checks. Nothing on this page is a claim about a live or organizer-supplied API.

Boundary testing

One account requests another account's private record. The run proves ownership first, then the disclosure, then compares the same request against the secure route.

How a finding becomes proof

A finding is never a status code on its own. Each step below is a check that the backend stores, hashes and can re-open.

  1. 01

    Authenticate

    Two distinct identities, each with its own token. Nothing is shared.

  2. 02

    Verify ownership

    Each account reads its own record first. That baseline is what a disclosure is measured against.

  3. 03

    Attempt the boundary

    The requesting account asks for the other account's resource. The response is recorded; it is not judged yet.

  4. 04

    Confirm the disclosure

    Only a private marker that matches the verified owner baseline is a disclosure. A 200 alone is never a finding.

  5. 05

    Compare the secure route

    The same request against the corrected endpoint must be refused — that denial is the evidence the vulnerable route is the anomaly.
